# Визуальная база проекта — готовая Design System «Вистерия» (Claude Design)

Дата фиксации: 25.08.2026. **Пересмотрено 03.09.2026** — Stitch исключён из процесса (см. `09_workflow-tooling.md` §1). Файл ранее назывался `12_design-system-stitch-base.md`.

Отвечает на исходный запрос заказчика: *«я хочу заложить базу, чтобы инструмент дизайна не фантазировал»*. Запрос остался в силе — сменился только инструмент, который эта база ограничивает: теперь это **impeccable** (компоновка) и **shadcn** (компоненты), а не Stitch.

**Роль этого документа в новой схеме:** он описывает **Слой 1** из `09_workflow-tooling.md` §1 — неизменяемую визуальную базу. Ни shadcn, ни impeccable не имеют права вводить цвета, шрифты, радиусы или тени помимо зафиксированных здесь.

## 1. Что это

Пользователь уже собрал (в отдельном инструменте — **Claude Design**, claude.ai/design) полноценную дизайн-систему «Вистерия». Она построена на тех же материалах, что и весь этот проект: та же папка `website_visteria/` была подключена туда как read-only источник (`01_brand/`, `02_company/`, `03_social-media/`, `05_website-plan/`, плюс загруженные `лого.jpg` и `фирменный стиль.pdf`).

**Ссылка (приватная, доступна пользователю):** https://claude.ai/design/p/e2a6dc51-eefc-4f70-884d-6c0e5455de59

Ценность именно этой формы: в отличие от текстового брендбука (`01_brand/brand-guidelines.md`), здесь зафиксированы конкретные, готовые к копированию значения — hex-цвета, CSS-токены отступов/радиусов/теней, инвентарь UI-компонентов, шрифтовые стеки — а не общие словесные описания, которые модель может интерпретировать по-своему.

## 2. Что реально внутри дизайн-системы

**Файловая структура** (компилируется автоматически в токены/компоненты/UI-кит):
- `styles.css` — точка входа, список `@import` на все токен-файлы.
- `tokens/colors.css, typography.css, spacing.css, base.css` — CSS custom properties.
- `assets/logo/` — растровый логотип (векторной версии нет, см. §4).
- `guidelines/` — спецификация-карточки для вкладки Design System.
- `components/` — переиспользуемые React-примитивы.
- `ui_kits/website/` — визуальная реконструкция сторфронта.
- `SKILL.md` — портативный skill-файл (можно использовать в Claude Code напрямую).

**Цвет (Visual Foundations):** 4 фирменных цвета печатного брендбука — белый `#FFFFFF`, чёрный `#000000`, зелёный `#366729`, фиолетовый `#9556B4`. Для экрана добавлены тоновые шкалы (hover/surface-состояния) — осознанное цифровое расширение поверх брендбука.

**Уточнено по факту выгрузки 03.09.2026** (`01_brand/design-tokens.css`) — три вещи оказались не такими, как описывалось здесь ранее:
- шкалы имеют **пять ступеней** (100, 200, 500, 700, 900), а не девять, и **фирменный цвет стоит на ступени 700**, не на 500;
- в системе есть цвета сверх четырёх фирменных: кремовый `--vs-cream #fbf8f3`, чернильный `--vs-ink #1c1a17`, нейтральные `--vs-stone-600 #6b655c` / `--vs-stone-300 #d9d3c8` и цвет ошибки `#b3452f`. **Фон страницы — кремовый, а не белый; основной текст — чернильный, а не чёрный.** Чистый чёрный в интерфейсе не используется вообще;
- есть семантический слой (`--color-primary`, `--color-secondary`, `--color-link` и т.д.), где **фиолетовый назначен основным акцентом, а зелёный — вторичным**. Печатный брендбук такой иерархии не задаёт.

Полная раскладка — `01_brand/DESIGN.md` §3.

**Типографика:** двухролевая система — Bergamasco (дисплейный, только в логотипе/крупных заголовках) и Caviar Dreams (текст). Временная замена на Google Fonts (Playfair Display / Montserrat) **больше не нужна** — подлинные файлы шрифтов получены 02.09.2026, см. §4.

**Логотип:** венок (зелёная веточка слева + фиолетовая ветка вистерии с цветами справа), капитель-засечки «ВИСТЕРИЯ» в центре, рукописный слоган по нижней дуге; охранное поле = ширина буквы «В»; 7 регламентированных цвет/фон-версий — совпадает с уже задокументированным в `01_brand/brand-guidelines.md`.

**Фирменный паттерн:** стилизованная буква «я» → силуэт бабочки, модульная сетка, фиолетовый или белый на цветном фоне, пониженная насыщенность как фоновый акцент — **описан, но не воссоздан как файл-ассет** (архив с исходниками не читается, см. §4).

> Отдельно отметить для дизайн-агента: фирменный паттерн — бабочка. Это прямо связывает согласованную анимацию бабочек из `prototypes/` с фирменным стилем: анимация не декоративная прихоть, а движущийся фирменный знак. Ещё одна причина не переделывать её (`09_workflow-tooling.md` §1, «Строгий запрет»).

**Цифровые UI-паттерны, которых нет в печатном брендбуке (обоснованное расширение под экран):**
- Радиусы: 4px мелкие элементы / 10px карточки / 20px крупные блоки-hero / pill только для бейджей и ценников. **Обязательны.**
- Тени: тёплые, рассеянная составляющая тонирована фирменным зелёным. Точные значения (выгружены 03.09.2026): `--shadow-sm: 0 1px 2px rgba(28,26,23,.06)`, `--shadow-card: 0 1px 3px rgba(28,26,23,.05), 0 12px 28px rgba(54,103,41,.10)`, `--shadow-elevated: 0 24px 60px rgba(28,26,23,.16)`. Холодный серый не использовать. **Обязательны.**
- Границы: тонкий hairline 1px (`--vs-stone-300`), без цветных левых акцент-бордеров. **Обязательны.**
- Blur: только на подложке модальных окон (backdrop-blur). **Обязательно.**
- Анимация/hover/press: `cubic-bezier(.4,0,.2,1)`, 150–240ms; hover = переход в `-hover`-токен цвета (не просто затемнение прозрачностью); press = `scale(.98)`. **Обязательны.**
- Компоновка: контент до 1200px, много воздуха вокруг фото (фото — герой), текст никогда не поверх фото без затемняющей подложки.

⚠️ **Разграничение по компоновке (введено 03.09.2026).** Последний пункт списка — единственный, который пересекается с зоной ответственности impeccable (`09_workflow-tooling.md` §1, Слой 3). Он разделён надвое:
- *Ширина контейнера 1200px и «много воздуха вокруг фото»* — **отправная точка, а не ограничение.** impeccable вправе её переопределить, если этого требует композиция: за компоновку отвечает он.
- *«Текст никогда не поверх фото без затемняющей подложки»* — **обязательное правило.** Это требование читаемости и бренда, а не вкусовое решение по раскладке, и оно не переопределяется.

**Iconography:** в брендбуке иконографики нет (это гайд по логотипу/полиграфии) — для UI выбран набор **Lucide** (тонкая линия, CDN) как ближайшая нейтральная замена, явно помечено как замена, а не находка в исходниках. Удачное совпадение: Lucide — иконочный набор по умолчанию и в shadcn, так что слой 1 и слой 2 здесь не конфликтуют.

**Инвентарь компонентов (`components/`)** — важно: **исходников (Figma/существующий код сайта) не было**, поэтому это не скопированный инвентарь, а осознанно подобранный стандартный набор под сторфронт цветочного магазина:
- `forms/` — Button, IconButton, Input, Select, Checkbox
- `feedback/` — Badge, Dialog
- `commerce/` — PriceTag, ProductCard
- `navigation/` — Tabs

> **После 03.09.2026 этот список читается иначе.** Раньше он был жёстким белым списком, ограничивающим генерацию. Теперь поведенческая часть компонентов приходит из shadcn (слой 2), и список выше следует понимать как **минимальный набор, который обязан существовать и быть выкрашен в токены «Вистерии»**, а не как потолок. Компоненты вне списка (Data Table, Charts, Sidebar, Toast, Command palette) добавляются из shadcn по мере необходимости — это ожидаемо, а не отклонение.

**UI-кит (`ui_kits/website/`):** визуальная реконструкция сторфронта — хедер, каталог с фильтром по цене/наличию, карточка товара (модалка), корзина-дровер, футер. Товарные данные — моки в `products.js`, собранные на основе реального каталога VK. **Явно помечено самой системой:** сайт ещё не разработан, это первая визуализация на основе брендбука и `05_website-plan/`, а не копия существующего продукта.

⚠️ **Важно при новой схеме:** этот UI-кит **не является эталоном компоновки**. Он показывает, как токены выглядят в деле, и полезен как проверка цвета/типографики/плотности — но раскладку экранов проектирует impeccable с нуля. Передавать этот UI-кит агенту как «воспроизведи эту композицию» **нельзя**: это ровно тот усреднённый лейаут, от которого заказчик и уходит.

**Content Fundamentals (тон текста):** реконструирован из реальных постов VK/Instagram (отдельного tone-of-voice гайда в брендбуке нет) — безличное «мы», короткие императивы, КАПС только для навигационных лейблов/хайлайтов, образные названия товаров («Ромашковое поле», а не «букет из ромашек»), эмодзи точечно (0–1 на строку, по смыслу).

## 3. Как перенести эту базу в проект — практическая рекомендация

Claude Design работает в отдельном окружении и не имеет автоматического доступа к репозиторию проекта. Чтобы база реально ограничивала, а не существовала параллельно, нужен явный перенос.

✅ **Выполнено 03.09.2026.** Токены выгружены в `01_brand/design-tokens.css` (дословный снимок) и `01_brand/DESIGN.md` (формат, который читает impeccable). Слой 1 заработал. Оставшиеся шаги — ниже.

1. **Экспортировать значения токенов в текстовый вид.** Скопировать содержимое `tokens/*.css` (или хотя бы конечные hex/px-значения из §2 выше) в файл внутри `01_brand/` этого проекта — например `01_brand/design-tokens.css` плюс сопроводительный `.md`. Это же содержимое затем ложится в `DESIGN.md` рабочего репозитория.
2. **Перенести файлы шрифтов.** `bergamasco-font-family.zip` и `caviar-dreams-font.zip` уже лежат в корне проекта; нужны распакованные `@font-face`-готовые файлы там, где будет собираться сайт.
3. **Составить `DESIGN.md`** — цвета, тоновые шкалы, типографическая шкала, радиусы, тени, границы, тайминги, обязательные правила из §2, плюс явный список запретов (не вводить новые цвета/шрифты/радиусы; не использовать дефолтную эстетику shadcn).
4. **Составить `PRODUCT.md`** — командой `/impeccable init` или вручную: что за продукт, кто пользователь (розница и B2B), какие задачи решает. Источники — `00_overview.md`, `02_company/`, `04_features-catalog-storefront.md`.
5. **Явно передать открытые пробелы (§4) как известные ограничения**, а не давать инструментам их додумывать: отсутствие векторного логотипа и паттерна.

## 5. Связь с остальным планом

- Дополняет (не заменяет) `01_brand/brand-guidelines.md` — печатный брендбук остаётся источником истины по логотипу/цветам/шрифтам как концепции; эта дизайн-система — его цифровое, готовое к копированию расширение (токены, радиусы, тени, компоненты).
- Напрямую относится к процессу из `09_workflow-tooling.md` §1 (Слой 1 из трёх) и §1б (перенос дизайна в код `packages/ui-kit`) — значения этих токенов переносятся сначала в `DESIGN.md` для проектирования, затем в реальный код `ui-kit`.
- Готовое задание агенту, собранное по этим правилам — `16_ui-design-task.md`.
- Инвентарь компонентов (§2) — стартовая точка для `packages/ui-kit`, не исчерпывающая: там, где `06_admin-dashboard.md` и `05_personal-cabinet.md` требуют компонентов вне списка (KPI-плитка дашборда, бейдж наличия по складу, история бонусов и т.п.) — они берутся из shadcn и перекрашиваются, а не проектируются с нуля.
