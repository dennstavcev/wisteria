# Публичная витрина — функциональность

## 1. Каталог

- Категории (из `productfolder` МойСклад): букеты, композиции, растения в горшках, сопутствующие товары (открытки, игрушки, вазы — если есть в ассортименте), опт (для B2B-раздела).
- **Фильтры**, построенные на реальной структуре ассортимента «Вистерии» (см. `02_company/company-profile.md`):
  - по цене — готовые сегменты до 1500 / 1500–3000 / 3000–4000 / 4000–5000 / 5000+ ₽ (сегменты уже используются компанией в Instagram-хайлайтах и VK-подборках — переиспользуем знакомую покупателю логику);
  - по поводу (день рождения, 1 сентября, свадьба, соболезнования и т.д. — через доп. поле МойСклад);
  - по составу/цветку (розы, хризантемы, пионы...);
  - «в наличии сейчас» (отфильтровать по `available > 0` из кэша остатков).
- Карточка товара: галерея фото, цена, статус наличия **в разрезе склада** ("в наличии для самовывоза на Островского" / "под заказ"), состав, размер, кнопка "добавить в корзину", похожие товары.
- Живой индикатор остатка ("осталось 2 шт.") — важно для скоропортящегося товара, стимулирует покупку и снижает разочарование при недоступности.

## 2. Корзина и оформление заказа

- Гостевая корзина (без регистрации) + слияние с корзиной аккаунта при входе.
- Проверка актуальности остатка **в момент перехода к оформлению** (повторный запрос к локальному кэшу, не к МойСклад напрямую — см. `01_tech-stack-architecture.md`).
- Выбор: доставка / самовывоз (с выбором конкретного склада — Островского, 19а).
- Слоты доставки по дате/времени.
- **Доставка — без службы-агрегатора.** Решение зафиксировано пользователем (25.08.2026): собственной курьерской службы или интеграции с логистической платформой (СДЭК, Яндекс.Доставка API и т.п.) нет — по факту менеджер/оператор вручную вызывает **Яндекс Такси/Яндекс Доставку** под конкретный заказ и отправляет букет клиенту. Для сайта это означает: **API-интеграция с логистикой не нужна для MVP** — вместо неё в админке нужен операционный шаг "вызвать курьера вручную" с местом для заметки (см. `06_admin-dashboard.md` §3, поле `courier_dispatch_note` в `03_database-schema.md`). Слот доставки на сайте — это ожидание клиента по времени, а не бронирование через API логистической платформы.
- Комментарий к заказу (открытка, пожелания по букету).
- Промокоды и списание бонусных баллов (для авторизованных, см. `05_personal-cabinet.md`).
- **Оплата: онлайн через Сбербанк Эквайринг** (провайдер зафиксирован, см. `11_payment-sberbank.md`) или "оплата при получении".
- Мгновенное подтверждение заказа на сайте (не дожидаясь ответа от МойСклад — заказ уже "принят в обработку", фактическая синхронизация в МойСклад идёт асинхронно, см. `02_moysklad-integration.md` §7).

## 3. Оптовый (B2B) раздел

Учитывая, что «Вистерия» реально ведёт оптовые продажи другим цветочным магазинам (собственный склад на Ижевской, прямые поставки от теплиц — см. `02_company/company-profile.md`):

- Отдельный раздел `/opt` с оптовым прайс-листом (`price_wholesale` из БД, соответствует отдельному типу цены в МойСклад).
- Доступ к оптовым ценам — только после регистрации и одобрения заявки (см. `05_personal-cabinet.md`, `wholesale_status`).
- Минимальная партия/сумма заказа для опта (настраиваемый параметр).
- Возможность выгрузки оптового прайс-листа в Excel/PDF — частая потребность B2B-покупателей.

## 4. Контент и доверие

- Информация о компании из уже собранного контекста (`02_company/`): адреса, время работы (ежедневно 9:00–20:00), телефон, оптовый склад.
- Страница "О нас" с фирменным стилем (логотип, слоган «Радость в каждом лепестке», фирменные цвета/паттерн — см. `01_brand/brand-guidelines.md`).
- Отзывы клиентов (собрать вручную у заказчика — в соцсетях отзывы не были доступны без входа в аккаунт).
- Интеграция с соцсетями: ссылки на VK и Instagram, возможно — виджет последних постов VK.

## 5. SEO и производительность

- SSR/ISR карточек товаров и категорий (см. `01_tech-stack-architecture.md`) — критично, т.к. органический поиск "доставка цветов Челябинск" — вероятно значимый канал трафика.
- Микроразметка Schema.org (Product, Offer, availability) — влияет на отображение в поиске и агрегаторах.
- Адаптивная вёрстка (мобайл-трафик для цветочных магазинов обычно доминирует — заказы "в последний момент" с телефона).

## 6. Уведомления покупателю

- **Сообщение через Telegram-бот** (основной канал — у клиента уже есть привязка к боту через вход по Telegram Login Widget, см. `05_personal-cabinet.md` §1) при смене статуса заказа (подтверждён / собран / в пути / доставлен) — статус подтягивается из МойСклад через вебхуки (см. `02_moysklad-integration.md` §7).
- Email-подтверждение заказа.
- Для клиентов, вошедших через VK, — уведомление через личные сообщения сообщества VK (аналогичный принцип, отдельно уточнить техническую возможность на этапе разработки — API рассылки VK Bots).
