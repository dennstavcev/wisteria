# 0012. Корневой пример конфигурации принадлежит одному владельцу

Дата: 09.09.2026

## Контекст

Монорепо, несколько приложений, у каждого свои переменные окружения. Тасков было
несколько, каждый завёл свои имена — и ни один не вписал их в корневой `.env.example`:
файл не принадлежал никому, и обязанности его пополнять ни у кого не было.

## Решение

Корневой `.env.example` — единственный список имён, которые читает код, и у него есть
владелец. Заводящий переменную вписывает имя туда же и тем же изменением. Значений нет
ни у одного имени.

Имена из ТЗ, которые кодом пока не читаются, вынесены отдельным разделом и помечены как
таковые. Переменная, нужная только тестам и CI, помечена необязательной. Умолчания,
живущие в коде, — расписание синхронизации — в примере не повторяются: у них один
источник, и он в коде.

## Почему

Рассматривали и отвергли:

- **Оставить как есть: свой `.env.example` в каждом приложении.** Отвергнуто потому,
  что собирающий окружение обходит пять каталогов и всё равно не знает, полон ли
  список. Это не гипотеза: два таска вернулись с переменными, которых не было нигде,
  кроме кода.
- **Генерировать пример из кода.** Соблазнительно и невыполнимо в главном: имена из ТЗ,
  которые код ещё не читает, генератор не увидит — а именно они нужнее всего тому, кто
  готовит среду. Плюс сам генератор становится кодом, который надо поддерживать ради
  файла на несколько десятков строк.
- **Повторить умолчания в примере, чтобы файл читался как готовая конфигурация.**
  Отвергнуто: два источника правды разойдутся при первой же правке расписания, и
  разойдутся молча — пример продолжит выглядеть достоверно.
- **Написать правдоподобные значения вместо пустых имён.** Отвергнуто по правилу
  проекта и по опыту: правдоподобное значение живёт дольше, чем следует, и однажды
  уезжает в боевую среду.

## Последствия

- Общий файл оказывается на пути каждого таска: заводя переменную, исполнитель правит
  зону, которая не его. Порядок обязателен — прочитать файл непосредственно перед
  точечной правкой, чтобы не затереть параллельное изменение соседа.
- Пример не запускается копированием: умолчания остались в коде, а обязательные
  значения (регион хранилища в их числе) требуются явно и запасного не имеют.
  Осознанно: молчаливое умолчание в настройках хранилища дороже, чем отказ старта.
- Раздел имён из ТЗ будет расходиться с кодом, пока функциональность не написана.
  Пометка делает расхождение видимым, но убирать её придётся вручную по мере
  готовности — автоматически это не рассосётся.
