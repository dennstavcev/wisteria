# 0011. Ошибка авторизации МойСклад останавливает расписание до вмешательства оператора

Дата: 09.09.2026

## Контекст

Синхронизация ходит в МойСклад по расписанию и повторяет временные ошибки ограниченным
числом попыток. Токен доступа (`MOYSKLAD_API_TOKEN`) может быть отозван или протух — и
тогда отказ авторизации получает каждая задача расписания, одна за другой.

## Решение

Отказ авторизации не считается временной ошибкой. Он отменяет оставшиеся попытки
текущей задачи и ставит очередь на паузу целиком. Пауза живёт в Redis и переживает
падение отдельных задач; снимается она только стартом процесса — то есть человеком,
после перевыпуска токена. Прочие сбои — скачивание и зеркалирование изображений —
остаются в счётчиках и расписание не трогают.

## Почему

Рассматривали и отвергли:

- **Повторять как всякую сетевую ошибку.** Отвергнуто: отказ авторизации не
  самоисправляется, повторы бессмысленны по определению, а их цена — расход лимита API
  и журнал, в котором настоящая причина тонет в сотнях одинаковых записей.
- **Продолжать по расписанию, помечая прогоны неуспешными.** Отвергнуто по двум
  причинам сразу: сервис часами стучится в чужой API невалидным ключом — так теряют не
  данные, а доступ; и никто не приходит чинить, потому что неуспешный прогон в журнале
  выглядит ровно как вчерашний.
- **Снимать паузу автоматически по таймеру.** Отвергнуто: токен сам не перевыпустится,
  и таймер лишь возвращает цикл отказов — теперь ещё и периодический, то есть похожий
  на норму.
- **Ронять процесс воркера.** Отвергнуто: супервизор поднимет его обратно, и выйдет тот
  же цикл, только с потерей состояния очереди при каждом обороте.

## Последствия

- Останов ручной по замыслу: с момента отзыва токена и до вмешательства человека
  остатки на витрине устаревают. Выбрано сознательно — устаревший остаток честнее
  пустого каталога.
- Появляется эксплуатационная процедура, без которой сайт не восстановится сам:
  перевыпустить токен, положить в окружение, перезапустить сервис. Её место — в
  инструкции эксплуатации; ненаписанная, она превращает это решение в тихую остановку
  синхронизации.
- Нужен внешний сигнал: пауза в Redis сама никого не будит, а «расписание молчит»
  снаружи неотличимо от «изменений нет».
- Возврат после долгой паузы попадает под суточное ограничение из записи 0007: первый
  прогон после перевыпуска будет полной сверкой, а не инкрементом.
