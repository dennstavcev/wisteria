# 03 — Управленка: каркас и список товаров

**Требования:** R01, R01.10i, R01.14i
**Blocked by:** 01
**Зона:** `apps/admin`, `apps/api/src/admin`
**Волна:** 2
**Status:** ready

## Что должно заработать

Флорист открывает управленку, видит список товаров, находит нужный поиском и отбирает
проблемные карточки фильтрами. Роль работает: денежных полей в ответе нет.

## Из брифа, дословно

> «запусти второй этап»
> «Служебный вход сейчас»
> «Заводим, без второго фактора»

## Разделы спецификации

Истории 28, 28а, 38–39б. Решения §Управленка — отдельное приложение и §В Этапе 2 у
флориста есть служебный вход. Границы: модуль `content`.

## Критерии приёмки

- [ ] `apps/admin` перестаёт быть пустым каркасом: React и Vite, приложение собирается и
      запускается, команды описаны в его README.
- [ ] Список товаров с пагинацией, поиском одновременно по названию сайта и названию
      МойСклад, фильтром по публикации.
- [ ] Шесть фильтров из `18_admin-catalog-content.md` §2: без фото, без описания, нулевой
      остаток, без полей для поиска, по складу, по категории. Массовые действия Этапа 2:
      публикация, бейдж и `sort_weight`; добавление в подборку остаётся Этапу 6 вместе
      с самими подборками.
- [ ] Роль проверяется на сервере на каждом эндпойнте. Флорист не получает себестоимость,
      маржу и клиентов, и это проверено тестом на ответе, а не на кнопке.
- [ ] Вместо заглушки работает служебный вход флориста: реквизиты живут только в серверной
      конфигурации, роль берётся из действующей строки `staff_allowlist`, сервер выпускает
      сессию в защищённой cookie; роль из запроса не принимается.
- [ ] `florist` входит без второго фактора. Служебный вход не открывает `manager`/`admin`:
      для них обязательный TOTP остаётся требованием следующего этапа входа.
- [ ] Ошибка бэкенда показывается по-русски, без внутренностей.
- [ ] Тесты: HTTP на фильтры и на белый список полей роли; сборка управленки проходит.

## Границы

Не трогать: `packages/db`, `apps/web`, `packages/ui-kit`, `apps/sync-worker`, бренд и дизайн
витрины. Схему базы не менять. Не коммитить.
