## Что должно заработать

Флорист правит карточку: название, описание, фото, бейджи, порядок, поля для поиска. Видит,
что сейчас показывает сайт — своё поле или поле МойСклад. Публикует, когда готово. Менеджер
видит, кто что менял, и откатывает.

## Критерии приёмки

- [ ] Правка уходит в слой сайта. Зеркало МойСклад не трогается ни при каких условиях: правки
      там не выживают синхронизацию и падают молча. Это главная ловушка проекта.
- [ ] В форме видно, откуда взято текущее значение: поле сайта или поле МойСклад.
- [ ] Правка переживает полный прогон синхронизации. Проверено тестом, а не рассуждением.
- [ ] Черновик сохраняется сам, недописанное не теряется при закрытии вкладки. Есть
      предпросмотр «посмотреть на витрине» через `v_product_public`.
- [ ] Фото: загрузка, в том числе с камеры телефона; очередь отправки переживает обрыв связи;
      точка фокуса для кадрирования; alt-текст. Связь только через `product_site_image` —
      колонки `images[]` в слое сайта нет и заводить её нельзя.
- [ ] Бейджи берутся из справочника `badge` с цветовым токеном, а не печатаются заново.
      У полей для поиска есть предел длины и счётчик.
- [ ] Публикация блокируется, если нет фото, цены, адреса страницы или связи с МойСклад.
      Причина отказа названа человеческим текстом.
- [ ] Товар исчез из МойСклад: карточка не удаляется, зеркало архивное, публикация снята.
      Товар кончился, но не исчез: карточка жива, помечена как отсутствующая, вместо кнопки
      покупки — подбор похожего.
- [ ] Каждое изменение пишет ревизию в `content_revision` с автором и временем. Откат к
      прошлой версии работает и сам записывается ревизией.
- [ ] Тесты: приоритет полей, сохранность правки после синхронизации, блокировка публикации,
      откат, отсутствие денежных полей у флориста.
