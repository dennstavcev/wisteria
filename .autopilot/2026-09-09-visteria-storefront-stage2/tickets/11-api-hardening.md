## Что должно заработать

1. **Сессия управленки.** Повреждённая percent-кодированная cookie сессии даёт «не
   авторизован» (401), а не URIError и 500. Параметры scrypt (`N`, `r`, `p`) и длина ключа
   из `ADMIN_STAFF_PASSWORD_HASH` проверяются на верхние границы до вычисления; хеш
   вне границ — ошибка запуска с именем переменной, без значения.
2. **Корзина.** Количество вне диапазона PostgreSQL `int4` отклоняется как `invalid_query`
   (400) до обращения к базе.
3. **ИНН.** Одно правило: `packages/shared-types` экспортирует проверку ИНН (10 или
   12 цифр), её используют контроллер опта в API, серверное действие и `pattern` формы
   заявки в `apps/web/src/app/opt/`. Три несогласованных копии удаляются.
4. **Редактор карточки.** Бейдж, который был назначен карточке и позже выключен в
   справочнике, не блокирует сохранение других полей: сервер принимает полный
   autosave-патч флориста с таким бейджем, отклоняя только *добавление* неактивного
   бейджа. Неизвестный `moyskladId` на `ensure` — документированный 404, не 500.
5. **Статусы заказа.** Reader состояния заказа МойСклад импортируется в API через
   объявленную workspace-зависимость (`@visteria/sync-worker` в `apps/api/package.json`
   и `exports` пакета), а не по относительному пути в `dist` соседнего приложения. Если
   reader недоступен (нет `MOYSKLAD_API_TOKEN`), API пишет в журнал одно предупреждение
   при старте, а не молчит.
6. **Вебхук.** Сырое тело запроса (`rawBody`) сохраняется только для маршрута вебхука
   МойСклад, а не копируется для каждого JSON-запроса всех контроллеров.
7. **Опт.** Поле `exports` с путями API и сырым токеном в JSON заявки убирается: витрина
   его не читает и строит свои адреса. Если убрать нельзя без поломки витрины — оставить
   и объяснить в CONCERNS.

8. **Заявка оптовика с витрины (находка слепой приёмки 20.09.2026).** Форма на `/opt`
   при отправке падает с 500: `apps/web/src/app/opt/actions.ts` помечен `'use server'`, но
   экспортирует константу `EMPTY_VALUES`, а Next.js допускает в таком файле только
   async-функции (то же правило уже описано для корзины: разбор вынесен отдельным
   модулем). Константу вынести, форма отправляет заявку и показывает результат.
   Тест: все экспорты `actions.ts` — функции.
9. **Вебхук без настройки.** `POST /webhooks/moysklad` при пустом `MOYSKLAD_WEBHOOK_TOKEN`
   отвечает контролируемой ошибкой (503 `not_configured` или 404 — выбрать и записать в
   README API), а не 500 `internal`; в журнале — имя переменной.
10. **Скрипты запуска.** `scripts/local-up.ps1` и `scripts/local-down.ps1` сохранить
    в UTF-8 с BOM: PowerShell 5.1 читает файл без BOM как ANSI и падает на кириллице
    (`local-down.ps1` сейчас не выполняется вовсе). Содержимое не менять, кроме кодировки;
    проверить `powershell -ExecutionPolicy Bypass -File scripts\local-down.ps1` — хотя бы
    разбор без ParserError (сам стек можно не останавливать: используйте `-WhatIf`-подобную
    проверку `[System.Management.Automation.Language.Parser]::ParseFile`).

## Критерии приёмки

- [ ] HTTP-тесты: повреждённая cookie сессии → 401; количество `2^31` в корзину → 400
      с `invalid_query`; `ensure` с неизвестным `moyskladId` → 404; патч карточки с ранее
      назначенным неактивным бейджем и новым названием → 200, добавление неактивного
      бейджа → 4xx.
- [ ] HTTP-тест входа проверяет истёкшую `expires_at` сессии; `ensure` покрыт отдельными
      утверждениями 401 и 403 и отсутствием записи при отказе; тест `updatedAt` доказывает
      запасной путь на `products.updated_at`, а не сравнивает поле с самим собой.
- [ ] Форма `/opt` отправляет заявку (HTTP-тест серверного действия или проверка экспортов); вебхук без токена → не 500.
- [ ] Правило ИНН существует в одном месте; ИНН из 11 цифр отклоняется и в API, и в форме.
- [ ] `pnpm build && pnpm test` зелёные; `pnpm --filter @visteria/web test` зелёный;
      `pnpm typecheck` и `pnpm lint` зелёные.
- [ ] Ни одного нового значения секрета ни в коде, ни в тестах; имена переменных — в
      `.env.example`, если появились новые.
