# Спецификация: начало разработки, Этап 1 без дизайна

Дата фиксации: 05.09.2026.

## Результат

Продолжить пустой каркас в соседнем репозитории visteria-website. Выполнить доступную локально backend-часть Этапа 1 из 07_roadmap-phases.md: инфраструктура разработки, вся схема БД и миграции, типизированный клиент МойСклад, полная синхронизация каталога и инкрементальная синхронизация остатков. Не объявлять Этап 1 закрытым без реальной проверки интеграции и ui-kit Клода.

## Истории и приёмка

- R01.1: разработчик устанавливает зависимости и запускает typecheck, тесты и build; команды проверены, версии закреплены lockfile. Приложения web/admin и ui-kit остаются каркасом.
- R02.1: локальные PostgreSQL 16 и Redis поднимаются через Docker Compose с healthcheck, постоянными томами и доступом только с loopback. CI выполняет проверки, не развёртывает production.
- R02.2: миграция на пустой PostgreSQL создаёт все сущности 03_database-schema.md, включая product_site, product_site_image, v_product_public, report_*, staff_allowlist и второй фактор. Повторный запуск безопасен. Человеческие поля не лежат в products; себестоимость/оптовые цены не попадают в публичный ответ. Незаполненные нормативы заказчика остаются NULL.
- R02.3: клиент читает JSON API 1.2, использует Bearer из MOYSKLAD_API_TOKEN, ограничивает запросы, обрабатывает 429 и временные ошибки с ограниченными повторами, timeout и безопасными ошибками. Тесты не требуют реального токена.
- R02.4: воркер переносит товары, категории, склады, типы цен и цены, не меняет product_site; повторная синхронизация идемпотентна. Неудачный прогон не делает оставшиеся товары удалёнными. Удалённые товары сохраняются как архивные зеркала для ссылок. sync_log отражает результат без секретов.
- R02.5: остатки берутся из report/stock/bystore/current с changedSince по правилам 02_moysklad-integration.md. Курсор сохраняется только после успешного прогона. Очередь BullMQ отделена от API. При ошибке МойСклад ранее сохранённые данные остаются доступны.
- R02.6: NestJS backend отдаёт health/readiness и ограниченную страницу опубликованного каталога только из БД. Неверные параметры отклоняются. Запрос покупателя не вызывает МойСклад. Денежные поля отчётности, закупочные и оптовые цены публично не выдаются.
- R03: ни дизайн, ни фирменные файлы, ни анимация, ни web/admin/ui-kit не меняются. В README оставлена точка передачи Клоду.

## Решения и границы

Стек из 01_tech-stack-architecture.md: Node/TypeScript, pnpm, NestJS, PostgreSQL 16, Redis/BullMQ. ORM — Drizzle (разрешён планом), миграции в packages/db. Существующие workspaces сохраняются.

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| db | вся схема, миграции, безопасная выборка каталога | schema, создание подключения, migrate | SQL и соединение |
| moysklad-client | транспорт JSON API 1.2 | клиент с пагинацией и ограничениями; внедряемый fetch | токен, backoff, таймеры |
| sync-worker | перенос каталога/остатков, журнал и курсор | запуск полного и инкрементального прогона, очередь | запись зеркала, расписание |
| api | публичные health/readiness и чтение каталога | HTTP с валидацией и белым списком полей | подключение к БД |
| infra | воспроизводимый локальный запуск и CI | compose и команды проверок | ресурсы сервисов |

Швы проверки: миграции на PostgreSQL, клиент через внедряемый транспорт, воркер через клиент и реальную тестовую БД, API через HTTP. Проверять ошибки, повторный прогон, отсутствие утечки закрытых полей и сохранность product_site.

Значения секретов не читаем и не просим. Неизвестные бизнес-данные не заполняем правдоподобными числами. Не определяем политику TOTP florist за заказчика.
