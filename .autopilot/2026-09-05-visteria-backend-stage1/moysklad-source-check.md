## D01 — физический остаток и границы курсора

В `05_website-plan/02_moysklad-integration.md` §5.1 значение `quantity` ошибочно названо физическим остатком. В официальном контракте:

| stockType | Значение | Поле локальной модели |
|---|---|---|
| stock | физическое количество без резерва и ожидания | stock_levels.quantity |
| reserve | резерв | stock_levels.reserved |
| freeStock | физическое количество минус резерв | stock_levels.available |
| quantity | доступность с учётом резерва и ожидания | не использовать как физический остаток |
| inTransit | ожидание | не подменяет доступный товар на складе |

Значение stockType по умолчанию — stock. Один запрос возвращает один выбранный показатель; поле в ответе носит имя показателя.

changedSince возвращает текущее абсолютное состояние изменившихся позиций, не дельту. Время — MSK, пример формата `2026-09-05 12:30:00`. Максимальная глубина — 24 часа; будущее недопустимо. Документация рекомендует перекрывать интервалы и периодически делать полную сверку без changedSince.

Следствие для реализации: устаревший более чем на 24 часа курсор требует полной сверки, а не отправки недопустимого параметра. Курсор успешного прогона сохраняется только после записи всех запрошенных показателей; небольшой нахлёст защищает границы. Это инженерная реализация ограничений источника.

## Ответ и нулевые значения

GET `/report/stock/bystore/current?stockType=freeStock` возвращает **массив верхнего уровня**, без rows/meta и без пагинации; весь краткий отчёт приходит одним ответом. Пример структуры с условными идентификаторами:

```json
[
  {"assortmentId":"PRODUCT_UUID","storeId":"STORE_UUID","freeStock":7},
  {"assortmentId":"PRODUCT_UUID","storeId":null,"freeStock":-2}
]
```

storeId=null означает резерв без назначенного склада; нельзя назначать его произвольному складу. Политику такого резерва нужно учитывать отдельно, не терять молча.

Без changedSince нули включаются параметром include=zeroLines. С changedSince нули включены автоматически. Удаление/архивация позиции или склада в выбранном интервале даёт нулевой остаток; повторный запрос сущности по UUID уже может не сработать. Товары без операций не выводятся даже с zeroLines.

По умолчанию возвращаются только пересчитанные значения. `withRecalculate=true` позволяет получить ещё пересчитывающиеся позиции с null вместо числа. null не означает ноль: прежнее значение сохраняется до следующего успешного обновления. Фильтры assortmentId/storeId принимают UUID, не URL; поддерживаются несколько значений.

## Изображения

Список `/entity/product/{id}/images` имеет обычные meta/rows. У элемента есть meta.downloadHref, filename, size, updated, miniature, tiny. Не следует ожидать отдельное поле id: идентификатор присутствует в meta.href/downloadHref.

GET по meta.downloadHref выполняется с авторизацией МойСклад и gzip. Успех — **302**, адрес файла в Location; он действует одну минуту. Последующее скачивание файла выполняется **без авторизации**. Не пересылать Bearer на хранилище при ручной обработке redirect; проверять HTTPS/разрешённые назначения, размер и тип файла.

На платном тарифе `fields=downloadPermanentHref` добавляет постоянную публичную ссылку в meta изображения; параметр совместим с expand=images. Такая ссылка скачивается без авторизации. Постоянная ссылка не отменяет требование проекта зеркалировать изображения в собственное S3.

Если вместо API id товара передан UUID интерфейса, список изображений может вернуть 308 Location на API URL с правильным id. Для синка использовать id из ответа API, а не uuidHref интерфейса.

## Проверки для исполнителя

- Мок краткого отчёта — массив, отдельно stock/reserve/freeStock; quantity с ожиданием не должен попадать в physical quantity.
- Инкремент переносит ноль и не прибавляет ответ к прошлому значению.
- Просроченный курсор переключает прогон на полный; ошибка второго показателя не продвигает общий курсор.
- storeId=null и ещё не пересчитанное null обрабатываются явно.
- Скачивание 302 не пытается разобрать ответ как JSON; Bearer отсутствует в запросе к Location; S3 хранит файл, не временный URL.
