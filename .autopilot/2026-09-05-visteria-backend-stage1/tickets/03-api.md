# 03 — Backend читает опубликованный каталог

Требования: R01, R02, R03. Волна: 2. Blocked by: 01.
Зона: apps/api.

Из брифа: «приступай к разработке таким образом чтобы соблюдать план который прописан там»; «дизайн пока не трогаем».

Спецификация: R02.6, границы. NestJS backend поверх готового db.

Приёмка:
- [ ] Health/readiness с безопасным ответом, readiness отражает доступность БД.
- [ ] Ограниченная пагинация каталога из v_product_public, параметры валидируются, только опубликованные карточки и белый список публичных полей.
- [ ] Нет обращения к МойСклад из HTTP, закрытые денежные поля отсутствуют в JSON.
- [ ] HTTP тесты положительного/пустого/неверного запроса, readyness failure и whitelist; typecheck/build/test проходят.

Не добавлять экраны, аутентификацию или функциональность следующих этапов. Не коммитить; зависимости согласовать с оркестратором. CONTRACT с командами и тестами.

Сквозные требования первоисточника 08_nonfunctional-security-ops.md: публичный rate-limit, структурированные безопасные логи и request id, ошибки БД не раскрывают SQL/секреты; CORS по явному конфигу для локальной витрины, без произвольного отражения origin. Документировать HTTP-контракт и команды в apps/api/README.md, чтобы Клод мог подключать витрину независимо. Это конкретизация R02.6, не новые экраны.

Не редактировать корневые manifest/lockfile/scripts: сообщить необходимые зависимости оркестратору, изменить только apps/api/package.json; общий install будет один после согласования с таском02.
