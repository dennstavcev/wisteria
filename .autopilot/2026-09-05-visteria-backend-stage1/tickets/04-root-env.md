# 04 — Имена переменных в корневом .env.example

Требования: R01, R02, R03. Волна: 3. Blocked by: 02, 03.
Зона: `.env.example` в корне репозитория кода. Больше ничего.

Из брифа: «приступай к разработке таким образом чтобы соблюдать план который прописан там».

Почему таск есть. Раскрой Этапа 1 отдал каждому исполнителю его пакет, и корень не достался никому.
Оба таска, 02 и 03, завели переменные окружения, описали их только в README своих пакетов и
сообщили, что корень вне их зоны. Правило `interfaces.md`: «Только пустые имена переменных в
.env.example». Сейчас разработчик, склонировавший репозиторий, не увидит половины конфигурации.

Приёмка:
- [ ] В `.env.example` есть все имена, которые читает код: DATABASE_URL, API_PORT, API_CORS_ORIGINS,
      API_RATE_LIMIT_WINDOW_MS, API_RATE_LIMIT_MAX, API_TRUST_PROXY, MOYSKLAD_API_TOKEN,
      MOYSKLAD_RETAIL_PRICE_TYPE_ID, MOYSKLAD_WHOLESALE_PRICE_TYPE_ID, MOYSKLAD_STORES,
      MOYSKLAD_IMAGE_HOSTS, S3_REGION и остальные S3_*, REDIS_URL, SYNC_FULL_CATALOG_CRON,
      SYNC_STOCK_INTERVAL_MS. Список сверяется с исходниками, а не с этим перечнем.
- [ ] Значений нет ни у одной переменной. Ни настоящих, ни правдоподобных примеров.
      Пустое имя и короткий комментарий, откуда значение берётся.
- [ ] Ничего не удалено из того, что уже было в файле.
- [ ] Порядок читаемый: база, API, МойСклад, хранилище, очередь и расписание.

Не трогать: apps/**, packages/**, корневые package.json, pnpm-lock.yaml, pnpm-workspace.yaml,
tsconfig.base.json, eslint.config.mjs, .github/**, бренд и дизайн. Не коммитить.
Секреты: только имена, значения не читать и не писать.
