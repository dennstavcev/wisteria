# Вистерия — сайт цветочного магазина (Челябинск)

Проектная база знаний и техническое задание: витрина розница + опт, личный кабинет,
управленка; источник данных о товарах — МойСклад. **Кода в репозитории нет и на этом
этапе быть не должно** — продукт здесь документы. Если таск кажется требующим кода,
он понят неверно.

## Архитектура

- **МойСклад — источник истины** по товарам, ценам и остаткам; сайт собственного учёта не ведёт.
- Пользовательский запрос никогда не идёт в МойСклад API: `sync-worker` наполняет PostgreSQL,
  витрина читает БД (`01_tech-stack-architecture.md` §1) — иначе не соблюсти лимиты API.
- **Слой сайта:** `products` — зеркало МойСклад (пишет только синхронизатор), `product_site` —
  карточка сайта (пишут только люди), связь по `moysklad_id`. Витрина читает представление
  `v_product_public`, где непустое поле сайта побеждает поле МойСклад.
- Цена, остаток, категория и наличие не переопределяются никогда — этих полей в `product_site`
  физически нет и заводить их нельзя.
- **Отчётность — витрина данных:** документы МойСклад по расписанию раскладываются в агрегаты
  `report_*`; каждая цифра раскрывается до первичного документа через `uuidHref`.
- Денежный контур опирается на девять сущностей МойСклад, которых интеграция не знала до
  04.09.2026: `supply`, `loss`, `enter`, `inventory`, `move`, `salesreturn`, `purchasereturn`,
  `purchaseorder`, `counterparty` в роли поставщика.
- **Три роли:** `florist` (контент и остатки), `manager` (плюс заказы и клиенты, без себестоимости
  и маржи), `admin` (всё). Проверка на сервере на каждом эндпойнте; денежные поля вырезаются
  в сериализаторе по белому списку роли, а не скрытием кнопок.
- Монорепо `visteria-website`: `apps/web`, `apps/admin`, `apps/api`, `apps/sync-worker`,
  `packages/db`, `moysklad-client`, `ui-kit`, `shared-types`, `infra/`.
- **Дизайн в три слоя**, ни один не переопределяет предыдущий: токены «Вистерии» (палитра,
  шрифты, ритм) → shadcn/ui (поведение, состояния, доступность) → impeccable (компоновка и характер).

## Терминология

Синонимы не вводятся: термин берётся из уже написанных файлов. Не «панель администратора»,
если везде «управленка».

| Слово | Значение здесь |
|---|---|
| управленка | админ-дашборд: операционный контур — `06_admin-dashboard.md`, денежный — `19_...` |
| витрина | публичная часть сайта; но «витрина данных» в `19_...` §1 — про агрегаты отчётности |
| слой, оверрайд | надстройка сайта над данными МойСклад (`product_site` поверх `products`) |
| списание товара, потери | документ `loss` МойСклад: увядший, испорченный, разбитый товар |
| списание баллов | расход бонусов покупателя, `bonus_transactions.reason` |
| опт, B2B | оптовое направление |
| таск | единица работы автопилота |

**Голое «списание» не употребляется.** Слово было занято бонусами (`03_database-schema.md` §4,
`05_personal-cabinet.md` §2.1) раньше, чем отчётностью; коллизия — расхождение №14 в `17_...` §5,
разведена в шапке `19_...` и уже стоила отдельной правки при переносе таблиц в схему БД.

## Что решено и не пересматривается

Развёрнуто, с основанием по каждой строке — `20_start-here.md` §4 и `17_readiness-audit.md` §7.

- Четыре архитектурных решения выше: источник истины, две таблицы, витрина данных, три роли.
- Сбербанк Эквайринг как платёжный провайдер; доставка без агрегатора (ручной вызов Яндекс
  Такси/Доставки менеджером); вход через Telegram и VK вместо SMS.
- Розница и опт запускаются одним релизом — решение заказчика 03.09.2026 отменило «опт
  отдельным Этапом 5».
- Google Stitch исключён полностью; палитра, шрифты и токены «Вистерии» — неизменяемая база.
- Анимация бабочек согласована, код переносится как есть и переделке не подлежит.
- Сервер Beget 2 vCPU / 4 ГБ, домен вистерия74.рф, TLS через Caddy — подняты и настроены.

## Подводные камни

- **`products` перезаписывается синхронизацией целиком** — правки руками там не выживают
  и падают молча, без ошибки и без записи в `sync_log`. Всё человеческое пишется в `product_site`.
  Именно эта архитектура была причиной, по которой управления товарами в ТЗ не было вовсе.
- Колонки `images[]` в `product_site` нет: фото связаны только через `product_site_image`.
- **Дата файла на диске ≠ актуальность.** Расхождения разрешаются по дате фиксации в шапке
  (`17_...` §3), и у восьми файлов её до сих пор нет (§3.1). Исключение одно: решение заказчика
  старше любого файла.
- **Ничего не удаляется.** Устаревший текст зачёркивается с датой и ссылкой на актуальный
  источник — так сделано в `00_README.md`, `06_admin-dashboard.md` §8, `10_pre-development-checklist.md`.
- В проекте есть ссылки на отсутствующие файлы (`SERVER_SETUP_RUNBOOK.md`,
  `вистерия фирменный стиль.zip`) — они каталогизированы в `17_readiness-audit.md` §6.
  Прежде чем сослаться на файл, проверь, что он есть; новых битых ссылок добавлять нельзя.
- Оценки §4 аудита — снимок состояния **до** достройки 04.09.2026 и намеренно не переписаны;
  пять вердиктов «Не готово» ждут первой пересборки (§11 п.1, итог — §12.4).
- **Никаких значений секретов:** переменная называется по имени (`MOYSKLAD_API_TOKEN`), значение —
  никогда. Действующий токен раскрыт 02.09.2026 и ждёт перевыпуска (`17_...` §8.1 п.11).
- Недостающие данные заказчика ставятся видимой заглушкой (`[ПЛАН ПРОДАЖ — впишет заказчик]`),
  а не правдоподобным числом.
- Язык документов — русский; английский только в идентификаторах: таблицы, поля, роли, эндпойнты.
